# QA 실행 기록 양식 · 복사해서 사용

> **현재 본 문서는 빈 양식입니다. 실제 수행했다는 증거가 아닙니다.**

| 항목 | 기록 |
|---|---|
| 테스트 ID | QA-000 |
| 실행 ID | RUN-YYYYMMDD-001 |
| 기능/요구사항 ID | FR-000 |
| 실행자 | 실제 수행자 기입 |
| 실행 시각·시간대 | YYYY-MM-DD HH:mm KST |
| 환경·브라우저·버전 | 예: 로컬 / Chrome 버전 |
| 테스트 데이터 | 합성 데이터만, 개인정보 제외 |
| 사전 조건 | 화면, 계정/비회원, 사용 정책·엔진 버전 |
| 입력/수행 단계 | 실제 재현 가능하게 기입 |
| 기대 결과 | 실행 전 정의 |
| 실제 결과 | 실행 후 기록 |
| 판단 | 확인됨 / 보완 필요 / 미확인 |
| 증거 파일 | 예: evidence/QA-000/RUN-...-redacted.png |
| 원인·수정 사항 | 실패한 경우 기록 |
| 재시험 실행 ID | 새로운 ID; 기존 실패 기록 삭제 금지 |
| 알려진 한계 | 검증 범위 밖 내용 |

## 상태 정의

- `미실행`: 실행하지 않음
- `확인됨`: 기대 결과를 실제 관찰하고 증거로 설명 가능
- `보완 필요`: 실제 결과가 다르거나 누락된 부분이 있음
- `미확인`: 시험했으나 증거가 부족하거나 원인을 구분할 수 없음

기술 캡스톤에서 활용한 '기대/실제/근거/개선/재시험' 형식을 포포 UX·AI 품질 검증에 맞게 정리한 것입니다.
