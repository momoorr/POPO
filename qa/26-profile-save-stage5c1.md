- 입력/인증/출력 필드 Node 검사: 15건.
- 모의 Chromium 시나리오: 15건. 실제 Kakao/DB에 접속하지 않음.

- 설치 검사는 별도의 `tests/test_installer_stage5c1.py`로 실행한다.

## 실제 POPO 계정에서 확인할 것 — 아직 미실행

가상 데이터: 이름 `테스트토끼`, 관계 `본인`, 양력 `2000-01-01`, 시간 `12:00`, 성별 `모름`, 지역 `대전광역시`.

1. 마이페이지 → 내 사주 입력하기 → 저장. 저장 메시지와 목록을 확인한다.
2. 웹 페이지를 새로고침하고 다시 마이페이지 → 저장된 사주 관리하기. 가상 정보가 유지되는지 확인한다.
3. 이름을 `테스트토끼 수정`으로 고치고 시간 모름을 선택해 저장. 다시 열었을 때 시간은 비어 있고 모름이 유지되는지 확인한다.
4. 삭제 확인창을 취소하면 데이터가 남아 있고, 승인하면 목록에서 제거되는지 확인한다.
5. 로그아웃하면 이전 계정의 목록/입력창이 남지 않는지 확인한다.
6. 별도의 테스트 계정 B로 계정 A의 프로필 ID에 대해 SELECT/UPDATE/DELETE가 거부되는지 검증한다. 실제 두 계정 RLS 검증 전에는 공개 배포를 확정하지 않는다.

실사용 캡처에는 이름·생년월일·토큰이 노출되지 않게 가상 정보만 사용한다. 기존 notes/vault_* 테이블이나 기존 회원을 삭제하지 않는다.
