# POPO Stage 5C — 회원별 출생정보 저장 CRUD

## 프로젝트 상태
- Stage 5B 카카오 로그인 성공, Stage 5B.1 지역 18개, Stage 5B.2 Pretendard 적용 뒤에 덧붙이는 로컬 코드.
- `popo_profiles`는 사용자가 기존 Supabase POPO 프로젝트에 이미 생성했고, RLS 정책과 GRANT의 형태가 예상 SQL과 일치함을 화면으로 확인했음.
- **이번 패치가 DB에 SQL을 재적용하거나 이전 `notes` / `vault_*` / 기존 Auth 사용자에 접근하지 않음.**

## 기능
- 마이페이지의 `+ 내 사주 입력하기`는 기존 예시용 `birth-dialog` 대신 새로운 회원 전용 사주 보관함의 새 입력 폼을 열도록 캡처 단계에서 연결.
- 같은 계정으로 다시 접속하면 `popo_profiles`의 이름·나와의 관계·날짜 기준·생년월일·출생시간·시간 모름·성별·출생지역을 조회할 수 있음.
- 수정·삭제 가능. 삭제는 사용자 확인 후 수행하며 참조 중인 보고서는 FK `on delete cascade` 영향을 받을 수 있음.
- UI에서 최대 5개 표시 및 신규 등록 제한. **DB 차원의 강제 5명 제한은 이 단계에 포함하지 않음.**
- 회원인지 `auth.getUser()`로 매 조회/쓰기 전에 서버 인증 재확인. 클라이언트 요청의 `user_id`는 사용자 입력이 아니라 인증 응답에서 획득하고, 모든 조회/수정/삭제 조건에 `user_id` 필터 적용. 최종 권한 보호는 Supabase RLS.
- 값은 `textContent`로 렌더링하여 저장된 이름을 HTML로 실행하지 않음.

## 미완료
- 개인 만세력 및 오행, 대운·세운 계산/검증/리포트 생성·저장 미연결. 이 단계는 **출생정보 프로필 저장만** 완료.
- 게스트 2문장 제한과 오늘의 운세는 다음 단계.
- 카카오 로그인 사용자 A가 사용자 B의 데이터를 실제 DB 경로에서 조회하지 못하는지는 실제 2계정 테스트 필요. 오프라인 모의 테스트로 이를 증명하지 않음.
- 웹사이트 배포, 로그인 사용량·비용 제한, 개인정보 처리 안내/보관정책 미완료.
