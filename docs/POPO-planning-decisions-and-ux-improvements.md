# POPO 프로젝트 기획 변경 및 개선 경험 정리

- **프로젝트:** POPO — 나를 읽는 AI 사주 상담
- **목적:** 웹·앱 서비스기획 취업용 포트폴리오 근거 정리
- **기준:** 2026년 11월 9일까지의 프로젝트 대화 및 확인된 GitHub 기록
- **문서 성격:** 기획 의사결정·문제 발견·개선 이력. 구현 완료와 검증 전 사항을 구분함.

## 1. 처음 기획과 개발 중 달라진 방향

| 영역 | 초기 방향 | 개발하면서 확장·변경한 방향 | 현재 상태 |
|---|---|---|---|
| 사주 결과 | 명식과 쉬운 풀이 제공 | 캐릭터·일주·오행·상세 정보의 정보 구조와 배치 개선 | 결과 화면 로컬 수정 진행, 배포 검증 별도 필요 |
| 만세력 | 기본 사주 네 기둥 표시 | 십성·지장간·12운성·신살·대운·세운·월운 등을 포함한 상세 정보 확대 제안 | 기획 제안, 미구현 |
| 캐릭터 | 달토끼 중심의 브랜드 | 12종 동물의 그림체·비율·정렬 기준 통일 | 디자인 시안 승인, 웹앱 적용·최종 검증 별도 확인 필요 |
| 오행 | 일반 개념과 분포 표시 | 도넛 그래프 두께·가독성 반복 개선 | 로컬 화면에서 사용자 만족 확인, 공개 배포 별도 확인 필요 |
| AI 상담 | 결과를 바탕으로 후속 질문 | 검증되지 않은 계산값을 개인화 답변에 사용하지 않는 정책 | 안전 경계·계산 후보 개발, 실제 상담 연동 미완료 |
| UX 검증 | 화면 구현 및 전환 확인 | 오류 메시지·접기/펼치기·궁합 내용·시각 정렬의 문제 발견과 개선 요구사항 기록 | 기능별 검증 범위 상이, 실제 외부 사용자 조사 미실시 |

## 2. 사용자가 직접 제안하거나 최종 결정한 사례

### 사례 A. 사주 결과 상단 화면의 2열 구조를 중앙 프로필형으로 변경

**초기 상태**
동물 캐릭터 왼쪽, 이름·일주 정보 오른쪽의 2열 구성.

**발견한 문제**
오른쪽 공백이 과하고, 이름 문구의 글자 단위 줄바꿈과 크기·굵기가 어색했음. 동물 얼굴과 둥근 사각형 안의 여백도 시각적으로 비대칭이었음.

**직접 판단·결정**
사주아이의 프로필형 화면을 참고하되 복제하지 않고, `캐릭터 → 이름 → 일주 → 일간 오행`의 세로형 정보 구조로 변경하도록 결정. 브라우저 개발자 도구에서 카드와 이미지 영역의 중심 좌표를 측정해 레이아웃 문제를 좁혀 감.

**AI 지원**
CSS·JS 수정안과 로컬 적용 ZIP 제작, 테스트용 코드 및 측정 명령 제공.

**확인된 결과와 한계**
중앙 프로필형 화면으로 전환한 로컬 스크린샷을 확인했으며, 카드 중심과 캐릭터 이미지 상자 중심 차이는 측정 당시 약 -3px로 확인됨. 다만 실제 얼굴과 배경 장식까지 포함한 시각적 균형은 별도로 검토함. 최근 캐릭터 디자인의 승인과 실제 웹앱 적용 검증을 혼동하지 않음.

**기획 관점의 배움**
CSS에서 가운데 정렬했다는 사실만으로 이용자가 보기에도 균형 잡힌 화면이 되는 것은 아님. 정보 구조, 그림 내부의 초점, 여백을 분리해 확인해야 함.

### 사례 B. 12종 동물 캐릭터의 그림체와 시각적 일관성 확립

**초기 상태**
동물마다 얼굴의 상하좌우 위치가 달랐고, 귀·꼬리 등이 잘리는 사례가 발생함.

**발견한 문제**
정렬을 수정하는 과정에서 AI가 그림체 자체를 변경한 시안을 제시해, 캐릭터 간 통일감이 훼손됨.

**직접 판단·결정**
새 스타일로 바꾸는 것을 반대하고 기존 부드러운 파스텔 3D 그림체·표정·색감을 유지하도록 요구. 구름·별 장식과 라운드 배경, 12종의 동일한 배치 규칙을 결정하고 최종 시안을 승인함.

**AI 지원**
동물별 위치 보정 시안과 이미지 자산, 설치 패치 작성 지원.

**확인된 결과와 한계**
12종 통일 디자인 시안은 승인됨. 실제 웹앱에 모두 정상 반영되었는지는 최종 적용 및 화면 확인 기록이 필요함.

**기획 관점의 배움**
부분적인 시각 개선보다 제품 전체의 브랜드 일관성과 승인된 디자인의 보존이 우선될 수 있음. 요청 범위에 없는 디자인 변경은 기획 검토 대상임.

### 사례 C. 오행 분포 도넛 그래프의 가독성 개선

**발견한 문제**
도넛 그래프의 고리가 지나치게 두꺼워 결과를 읽는 데 답답하게 느껴졌음.

**직접 판단·결정**
가운데 공간을 넓히되 지나치게 가늘어지지 않도록 두께를 낮추라고 반복 요청함.

**AI 지원**
도넛 중심 크기 관련 CSS 수정과 로컬 테스트.

**확인된 결과와 한계**
사용자가 수정된 오행 그래프를 원하는 수준이라고 직접 확인했음. 이 확인은 기획자의 로컬 화면 검토이며, 외부 사용자 대상 사용성 개선 수치가 아님.

**기획 관점의 배움**
정보의 존재뿐 아니라 그래프의 비율과 가독성도 사용자 경험의 일부임.

### 사례 D. 상세 만세력의 정보 깊이 확대

**초기 상태**
네 기둥과 기본 오행·쉬운 풀이 중심.

**직접 제안**
사주아이 화면과 비교하며 기본 명식만으로는 정보가 부족하다고 판단하고, 십성·지장간·12운성·신살·대운·세운·월운 등을 확인할 수 있는 상세 만세력 방향을 제안함.

**선택한 기획 방향**
초심자를 위한 기본 화면은 유지하면서 필요할 때 상세 정보를 열 수 있도록 정보층을 나눔. 경쟁사 화면 자체를 복제하지 않음.

**현재 상태**
추가 기능 기획 단계. 산출 규칙, 데이터 검증, 실제 구현 및 사용자 검증은 남아 있음.

**기획 관점의 배움**
쉽게 설명하는 것과 필요한 정보를 충분히 제공하는 것은 별개의 요구사항임. 정보 접근성을 유지하면서 상세도를 높이는 단계형 구조가 필요함.

### 사례 E. 클릭형 목업의 UX 오류 발견 및 개선 요구사항 정의

**GitHub QA 문서에 확인된 이슈**
1. 심화 설명을 펼쳐도 버튼 문구가 계속 '보기'로 표시됨.
2. 궁합 관계 유형을 바꿔도 결과 본문 대부분이 비슷함.
3. 생년월일 입력이 빠졌을 때 어떤 항목이 빠졌는지 안내하지 않음.

**기획 방향**
화면 상태에 맞는 버튼 명칭, 관계별로 구분되는 내용, 누락 필드에 대한 구체적인 오류 안내가 필요하다고 정의함.

**검증 상태**
2026-10-30 GitHub 기록 기준 UX 테스트 12건 중 PASS 3건, 부분 확인 3건, 미실행 6건. 이는 프로토타입의 일부 수동 기능 확인이며 실제 이용자 조사나 정량 성과가 아님. 후속 로컬 수정의 완료 여부는 버전별 증거와 별도로 연결해야 함.

## 3. 개발하면서 구체화한 서비스기획 기준

사용자가 정한 우선순위는 다음과 같음.

1. **사용자 편의성** — 원하는 행동을 쉽게 찾고 수행할 수 있는가?
2. **필요한 정보** — 정확하고 충분한 정보를 제공하는가?
3. **디자인 완성도** — 정렬·가독성·시각적 일관성이 확보됐는가?
4. **차별화** — 다른 서비스와 구별되는 경험이 있는가?

이 기준은 결과 화면 재설계, 상세 만세력 확대 제안, 캐릭터 일관성 유지, 오행 그래프 개선에 실제로 적용된 기획 판단으로 설명할 수 있음. 다만 사용자 편의성 개선의 객관적 효과는 외부 사용자 테스트로 아직 검증하지 않았음.

## 4. 포트폴리오에 활용할 추천 사례

| 우선순위 | 사례 | 어필할 역량 | 증거 |
|---|---|---|---|
| 1 | 2열 결과 화면 → 중앙 프로필형 구성 | 정보 구조·UI 배치 판단 | 변경 전후 화면, 중심 좌표 측정, 로컬 적용 기록 |
| 2 | 상세 만세력 확대 제안 | 경쟁사 참고·요구사항 도출 | 참고 화면, 기능 요구사항·정책 문서 |
| 3 | 미검증 계산값의 개인화 사용 제한 | 신뢰성·정책 설계 | GitHub 계산 후보 검증 문서·커밋 |
| 4 | 12종 캐릭터 디자인 일관성 | 디자인 원칙·품질 관리 | 승인 시안, 수정 과정, 적용 전후 화면 |
| 5 | 오행 도넛 가독성 개선 | 데이터 표현·UX 개선 | 수정 전후 캡처, 사용자 확인 발언 |

## 5. 사용자 기여와 AI 지원의 구분

| 사용자 직접 수행/결정 | AI가 지원한 부분 |
|---|---|
| 기능 아이디어 제안, 서비스 기획 우선순위 결정 | 요구사항·화면 대안 정리 |
| UI 불균형과 오류 발견, 수정 요청 | CSS·JS 구현 패치 제작 및 코드 수정 보조 |
| 캐릭터 그림체와 최종 디자인 승인 | 캐릭터 이미지 시안·수정안 제작 지원 |
| 경쟁사 화면 참고와 상세 만세력 필요성 제안 | 기능 구성·정보 구조 대안 작성 |
| 로컬 PowerShell 실행, 브라우저 화면 확인·피드백 | 검증 명령어·테스트 자료 작성 |

개인 프로젝트로 진행했으며, 별도 개발자·디자이너와 협업한 팀 프로젝트로 표현하지 않음. AI가 작성한 코드를 사용자가 직접 구현했다고 기재하지 않음.

## 6. 검증·업데이트 시 주의사항

- 디자인 시안 승인 ≠ 실제 웹앱 전체 적용 완료.
- 로컬에서의 작동 확인 ≠ GitHub Pages 공개 배포.
- 기획자 개인의 화면 검토 ≠ 외부 사용자 테스트.
- 기능 요청·기획 확정 ≠ 기능 개발 및 산출 정책 검증.
- 오류 원인에 관한 추정은 테스트 수치나 실제 코드 검증과 구분.
