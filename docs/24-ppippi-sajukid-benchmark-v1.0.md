## 2. 어떤 점을 참고하고, 무엇을 독자적으로 설계할까?

| 기획 영역 | 벤치마킹으로 참고할 경험 | 포포만의 새 설계안(미검증 가설) |
|---|---|---|
| 첫 경험 | 출생 정보 → 내 명식 → 풀이 | 비회원 입력 후 **한눈에 보는 명식·오행 요약** 먼저 표시, 이어서 상세 보기 |
| 명리 정보 탐색 | 명식 용어, 신살·십성 등 상세 풀이 | 클릭한 글자의 **쉬운 뜻 → 실제 계산 근거 → 전문가 심화 → AI 질문** 연결 |
| 오행 분석 | 오행과 균형·강약에 관한 전통적 분석 | **8글자 표면 오행 분포 그래프**와 최다 등장 오행 카드. 강약·용신 판단과 명확히 구분 |
| 주제별 풀이 | 연애·재물·직업·관계 등 카테고리 | 한 화면 2~3문장 요약, 더 보기, 근거, 질문 연결로 읽기 부담 관리 |
| 궁합 | 대상 선택, 항목별 풀이 및 관계 유형 | 연인·배우자·가족·친구별 서로 다른 결과 항목, 소통 팁, AI 후속 질문; 점수 산식 검증 전 점수 미제공 |
| 캐릭터 | 귀여운 캐릭터로 진입장벽 완화 | **자체 브랜드 달토끼 포포** + 후속 60갑자별 자체 동물 캐릭터, 동일 일주 동일 캐릭터 ID |
| 운의 흐름 | 오늘의 운세·대운·연운·택일 | 날짜 기준·계산 버전이 있는 오늘/올해/대운 정보. 세운과 올해 총운은 동일 데이터의 다른 설명층 |
| AI 후속 상담 | 풀이 후 이어서 질문 | 명식·선택 카테고리·해석 근거를 연결하는 응답, 모르면 '계산되지 않음' 안내 |
| 수익화 | 건별 결제/일부 무료 기능 | 1차 MVP는 **유료 기능 미도입**. 검증 이후 기능별 이용 가치·비용·정책 비교 |

기존 두 서비스 모두 쉬운 사주 풀이와 후속 상담 요소를 제공하므로, 이것만으로 포포의 독점적 차별화라고 주장하지 않는다. **근거 투명성과 탐색 연속성**을 서비스 가설로 설정하고 테스트로 검증한다.

### 2026-11-10 1차 제출 목표를 지키기 위한 범위 관리

1. **오행 그래프 우선:** 지금 시험값(목1·화3·토3·금0·수1)을 **화·토 공동 최다**로 표시. 합계 8임을 명시하되 '강한 오행'·'성격 확정'으로 표현하지 않음.
2. **사주 계산 QA:** 명식 네 기둥의 공식 정책을 확정하고 라이브러리 산출과 독립 자료를 교차검증하기 전에는 실서비스 결과로 변경하지 않음.
3. **풀이·AI 흐름:** 검증한 명식 요소만 해석에 전달하고, 실제 API 미연동 상태는 시연으로 남김.
4. **궁합·운세 추가 기능:** 이미 완성된 클릭형 흐름을 유지하되 정확성 검증이 필요한 기능은 '준비 중' 표시.

## 4. 다음 구현: 오행 분석 그래프(BEN-02)

**화면:** `SCR-03` 내 사주 요약에서 `오행 분포 자세히 보기` 선택 → 기존 `elements` view 상단.

**정보 순서:** ① '계산 엔진 시험값(검증 전)' 안내 → ② **가장 많이 등장한 오행** 카드(복수 동률 허용) → ③ 목·화·토·금·수 막대 그래프 → ④ 오행별 2D 포포 풍경 탭.

**표시 규칙**
- 배열 순서는 목→화→토→금→수로 고정하고 개수 0도 숨기지 않는다.
- 대표값은 `Math.max(...counts)`에 같은 값을 가진 모든 오행을 찾아 표시한다. 이때 '대표 오행'이란 **표면 8글자 최다 등장**이라는 UI 용어로만 설명한다.
- 분모는 확인된 시주가 있을 때 8, 출생시간 미상 정책이 마련되면 해당 명식에서 실제 계산된 글자 수로 표시. 현재 엔진 시험은 시간 미상 값을 산출하지 않는다.
- 숫자·오행 명칭·접근 가능한 대체 텍스트를 제공하며 색만으로 구분하지 않는다.
- 시험 결과가 없으면 그래프 대신 `출생 정보에서 계산 시험을 완료하면 표시돼요` 안내(가상의 숫자 생성 금지).
- 계산 입력이 바뀌면 기존 그래프를 초기화한다.

**QA**
- QA-BEN-01: 1/3/3/0/1 입력 → '화·토 공동 최다' 표시, 막대 합계 8, 금 0 정상 표시.
- QA-BEN-02: 최댓값 단독/동률/불완전 데이터의 표시 동작.
- QA-BEN-03: 그래프가 시험값임을 알 수 있고 시각적 오해를 줄이는 레이블 제공.
- QA-BEN-04: 모바일 360px·390px에서 라벨/막대/숫자 겹침 없음.
- QA-BEN-05: 계산 입력 변경→기존 결과 사라짐.

## 5. 서비스기획 포트폴리오로 남길 증거

- **확인한 경쟁사 기능:** 날짜·링크·공개 소개/캡처 근거, 확인·미확인 구분.
- **문제 가설:** 용어 난이도, 결과 탐색 부담, 후속 질문의 연속성에 관한 가설.
- **기능 우선순위 결정:** 11/10 일정에 맞춰 계산·오행·풀이·AI 경로에 집중한 이유.
- **설계:** 사용자 플로우, 화면설계서, 빈/오류/시험 상태, 개인정보 처리 방식.
- **구현·검증:** 실제 동작 스크린샷, QA 실패·수정·재시험, 사용자 테스트(실행 후에만 성과로 기재).

## 6. 추가 검증이 필요한 사항

- 삐삐사주·사주아이 실제 앱의 모든 화면 전환, 최신 업데이트와 유료/무료 상세 정책.
- 두 서비스의 신강·용신·격국·신살·대운 산출 규칙과 품질은 외부 소개만으로 검증 불가.
- POPO의 사주 계산 정책(절기·자시·윤달·한국 시간 보정), 회원/기록/결제·AI 상담 데이터 보호 정책.
