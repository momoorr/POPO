**목표** 11월 10일까지 출생 정보 입력 → 검증된 명식 조회 → 쉬운 풀이·용어 설명 → AI 후속 상담의 핵심 흐름을 구현하고, 궁합의 기본 이용 흐름을 검증한다.

### 01 / WHY & WHAT

## 1. 프로젝트 개요

포포(POPO)는 출생 정보를 바탕으로 사주 명식을 확인하고, 관심 주제의 풀이를 읽은 뒤 AI와 후속 질문을 주고받는 개인화 명리 상담 웹 서비스다. 쉽고 친근한 표현과 단계별 정보 공개를 통해 초보 사용자의 이해 부담을 줄이는 것을 목표로 한다.

| **구분**      | **내용**                                                                           |
|---------------|------------------------------------------------------------------------------------|
| **서비스명**  | 포포(POPO) \| 나를 읽는 AI 사주 상담                                               |
| **플랫폼**    | 모바일 우선 반응형 웹(한국어)                                                      |
| **주요 대상** | 사주 용어에 익숙하지 않거나 직업·연애·재물 등 관심 주제를 간편히 탐색하려는 사용자 |
| **수행 형태** | 개인 기획·제작 프로젝트(개발과 문서 작성에 AI 도구 활용)                           |
| **공개 현황** | GitHub Pages에 클릭형 웹 목업 공개. 실제 사주 계산·AI API·사용자 검증은 미완료     |

## 2. 추진 배경 및 문제 정의

경쟁 서비스의 공개 화면과 제공된 벤치마킹 자료를 검토하며, 명리 정보의 양뿐 아니라 사용자가 내용을 이해하고 원하는 질문으로 이동하는 과정에 주목했다. 아래 문제는 현재 사용자 조사 이전의 기획 가설이다.

| **사용자 문제 가설**                              | **포포의 해결 방향**                                                |
|---------------------------------------------------|---------------------------------------------------------------------|
| **전문 용어가 어려워 명식을 읽기 어렵다.**        | 일간·오행·십성 등의 용어를 누르면 쉬운 설명과 심화 내용을 제공한다. |
| **자신에게 필요한 풀이를 찾기 어렵다.**           | 종합·연애·재물·직업·인간관계 등 관심 주제별 탐색을 제공한다.        |
| **풀이를 읽은 뒤 추가 질문이 어렵다.**            | 현재 명식과 선택한 주제를 AI 상담에 전달해 대화 흐름을 연결한다.    |
| **두 사람의 관계를 단순 점수로 이해하기 어렵다.** | 관계 유형에 맞춰 강점·갈등 요인·대화 팁을 구분해 제공한다.          |

## 3. 1차 목표

- 서비스: 비회원이 핵심 기능에 진입하고, 계산된 명식과 설명을 확인하며, AI에 추가 질문할 수 있도록 구현한다.

- UX: 달토끼 캐릭터와 신비로운 분위기를 유지하되 읽기 쉬운 타이포그래피·명확한 버튼·모바일 탐색을 우선한다.

- 검증: 기능별 테스트 결과, 오류·수정 이력, 실제 동작 영상/화면을 정리해 제출 가능한 근거를 확보한다.

### 02 / SCOPE & USER FLOW

## 4. 핵심 기능과 구현 범위

11월 10일을 기준으로 실사용 가능한 핵심 흐름을 우선 구현한다. 계산 규칙이나 개인정보 정책이 검증되지 않은 기능은 화면만 제작했더라도 실제 서비스 기능으로 표시하지 않는다.

| **구분**        | **기능**       | **1차 구현 목표 / 처리 원칙**                                                            |
|-----------------|----------------|------------------------------------------------------------------------------------------|
| **핵심(P0)**    | 홈·모바일 UI   | 달토끼 포포, 주요 기능 진입, 반응형 레이아웃                                             |
| **핵심(P0)**    | 출생 정보 입력 | 양·음력 선택, 생년월일·시간/미상·지역 입력 및 유효성 검사. 실제 지원 범위 안내           |
| **핵심(P0)**    | 내 사주·명식   | 검증된 계산 엔진이 지원하는 년·월·일·시주와 오행 정보 표시; 미지원 범위는 별도 안내      |
| **핵심(P0)**    | 명리 용어 설명 | 일간·오행·십성 등 눌러서 쉬운 뜻과 심화 설명 보기                                        |
| **핵심(P0)**    | 기본·심화 풀이 | 종합·연애·재물·직업·인간관계 중심; 계산 근거와 전통 해석 구분                            |
| **핵심(P0)**    | AI 사주 상담   | 서버 측 모델 연결, 명식·선택 주제 문맥 전달, 응답 오류·재시도                            |
| **조건부(P0+)** | 관계별 궁합    | 연인·배우자·가족·친구 선택, 두 사람 입력·기본 설명·AI 질문. 규칙 미검증 시 시안으로 분리 |
| **후속(P1~)**   | 콘텐츠 확장    | 오늘의 운세, 토정비결, 대운·세운 심화, 타로, 회원·기록, 60갑자 전체 캐릭터               |

## 5. 핵심 이용 흐름

**홈 → 출생 정보 입력 → 입력 검증 및 사주 계산 → 내 사주 결과 → 용어 설명·관심 주제 풀이 → AI에게 추가 질문**

궁합 이용 흐름: 궁합 선택 → 관계 유형 선택 → 본인·상대 출생 정보 입력 → 검증된 비교 결과(또는 명시된 시연 화면) → 관련 AI 질문

## 6. 기능 공개 정책

- 사용 가능: 검증된 계산·AI 기능만 실제 결과로 제공한다.

- 준비 중: 토정비결·심화 운세 등은 별도 안내 화면을 제공하며 임의의 개인화 결과를 만들지 않는다.

- 시연용: 목업의 명식·점수·답변은 예시 데이터임을 화면에 명확히 표시한다.

### 03 / DESIGN & BUILD

## 7. 디자인·캐릭터 방향

서비스 분위기는 신비롭고 반짝이되, 주요 행동과 정보는 쉽게 찾을 수 있도록 설계한다. 주 색상은 네이비·라벤더·아이보리, 별빛 표현은 금빛 포인트로 제한한다.

| **구성**          | **설계 방향**                                                                                         |
|-------------------|-------------------------------------------------------------------------------------------------------|
| **대표 마스코트** | 새침한 고양이상 눈매, 긴 속눈썹을 지닌 달토끼 ‘포포’. 절구에서 방아를 찧는 대표 포즈를 신규 제작한다. |
| **일주 캐릭터**   | 60갑자별 동물 캐릭터는 후속 확장 범위. 1차에서는 대표 마스코트에 집중한다.                            |
| **명식 결과**     | 핵심 요약을 먼저 보여주고 용어·심화 내용은 선택 시 열리도록 구성한다.                                 |
| **궁합 결과**     | 한 줄 요약 → 관계별 항목 → 해석 근거 → 현실적 관계 조언 → AI 질문 순으로 구성한다.                    |
| **접근성**        | 모바일 터치 영역, 한글 가독성, 색상 외 레이블, 로딩·오류·빈 상태를 고려한다.                          |

## 8. 개발 구조와 안전 정책

| **영역**        | **구현 원칙**                                                                                                    |
|-----------------|------------------------------------------------------------------------------------------------------------------|
| **프런트엔드**  | 기존 GitHub Pages 목업을 개선하고 모바일 중심 화면과 상호작용을 구현한다.                                        |
| **계산 모듈**   | 언어모델이 아니라 별도 역법 엔진을 사용한다. 절기·자시·윤달·시간 미상 규칙의 지원 범위를 확인한다.               |
| **AI 상담**     | AI 키는 서버 측에 보관하고 계산된 구조화 명식을 입력으로 전달한다. 응답은 질문·근거·한계·후속 질문으로 구성한다. |
| **궁합 정책**   | 타인의 개인정보 수집을 최소화하고 저장 전에 명시적 동의를 고려한다. 근거 없는 100점 만점 수치는 제공하지 않는다. |
| **콘텐츠 기준** | 명식 계산값 / 전통 해석 / 현실적 사실을 구분한다. 건강·투자·합격·관계 결과를 확정적으로 예언하지 않는다.         |
| **기술 선택**   | 프런트엔드, API 서버, 모델·DB 제품은 구현·비용·보안 검토 후 확정하며 현재 사용 중인 것처럼 쓰지 않는다.          |

참고: ALEPH 캡스톤 가이드의 요구사항-시험-증거 연결 방법만 문서화에 활용한다. 포포는 별도의 개인 B2C 서비스 프로젝트다.

|------------------|--------------------------------------------------------------------------------------------|

## 11. 완료 판단 및 범위 조정

최소 완료 조건은 ① 사용자가 핵심 흐름을 끝까지 수행할 수 있음 ② 실제 구현된 부분의 계산·AI 동작을 검증함 ③ 주요 QA와 수정 이력이 남아 있음 ④ 미구현 기능을 별도 상태로 명시함이다.

11월 3일까지 계산 엔진의 정확성을 확보하지 못하면 결과를 목업으로 표시하고 검증 범위를 먼저 확정한다. 11월 7일까지 AI 연동이 불안정하면 데모를 실제 AI 서비스로 소개하지 않는다. 궁합은 같은 기준으로 실사용 기능과 시연 기능을 구분한다.

## 14. 수행 역할 및 기대 효과

개인 프로젝트로 사용자 문제 정의, 기능 범위·정책 설정, 화면 구조, 테스트 계획과 결과 정리를 수행한다. AI 도구를 활용해 문서 작성 및 코드·UI 제작을 지원받되, 실제 수행한 부분과 자동 생성·목업 부분을 구분해 기록한다.

이번 프로젝트를 통해 보여줄 역량은 단순 운세 앱 제작이 아니라, 복잡한 콘텐츠의 정보구조 설계, AI 기능의 책임 분리, 개발 범위와 우선순위 관리, 테스트 근거 중심의 서비스 개선 과정이다. 실제 성과 수치와 사용자 반응은 검증 후에만 기재한다.
