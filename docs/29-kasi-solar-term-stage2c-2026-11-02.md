# POPO Stage 2C — 한국 표준시 절기 시각 검증 (2026-11-02)

## 검증 배경

- 기존 실제 브라우저 테스트: Stage 2A 26/26 PASS, Stage 2B 156/156 PASS. 2026-11-02 제공된 Stage 2B 캡처는 `evidence/stage2b-hour-browser-pass-2026-11-02.png`에 보관한다.
- 기존 156건은 전통 시두법과 **무보정 KST 가정**에 따른 시주 규칙 검증이다. 출생 순간·절기 분 경계·지역 경도 보정을 증명하지 않는다.
- `lunar-javascript@1.7.7` 번들의 2026년 입춘 시각 `2026-02-04 04:02:08`, 한국천문연구원 공개 달력자료의 입춘 시각 `2026-02-04 05:02 KST`.
- 원본 라이브러리의 중국 표준시(UTC+8) 사용이 강하게 의심되지만, 문서화된 시간대 계약과 다른 연도에서도 성립하는지 확인해야 한다.

## 독립 기준과 비교 범위

- 출처: [한국천문연구원 2026년 달력자료](https://astro.kasi.re.kr/kor/life/post/calendarData?year=2026) 중 24절기 날짜/시/분 표.
- 2026년 24개 절기의 분 단위 기준값을 고정한 뒤, 미수정 번들의 `getJieQiTable()` 시각과 비교한다.
- `+60분`은 **QA에서 KST와 비교하기 위한 실험적 시각 이동**이며, 출생 시각이나 명식의 시주에 그대로 적용하지 않는다.
- 비교 조건: 이동 후 분 단위 반올림한 시간이 KASI 자료와 일치할 것.

## 2026-11-02 계산 라이브러리 직접 조사

GitHub 커밋 `00c4772`의 기존 `prototype/vendor/lunar.min.js`를 실행해 조사했다.

| 항목 | KASI 기준(KST) | 원본 라이브러리 | 비교용 +60분 |
|---|---|---|---|
| 소한 | 2026-01-05 17:23 | 2026-01-05 16:23:10 | 17:23:10 |
| 입춘 | 2026-02-04 05:02 | 2026-02-04 04:02:08 | 05:02:08 |
| 경칩 | 2026-03-05 22:59 | 2026-03-05 21:59:00 | 22:59:00 |
| 동지 | 2026-12-22 05:50 | 2026-12-22 04:50:14 | 05:50:14 |

- 24개 모두 비교용 +60분 적용 후 공개 분 단위 자료와 일치했다. 잔여 오차는 -30초~+21초로 확인됐다.
- 보정 전에는 24개 모두 KST 기준과 약 1시간 차이 난다.
- 입춘 당일 `2026-02-04 04:30 KST`는 KASI 기준 입춘 전이지만, 기존 원본 라이브러리의 `getEightChar()`는 이미 `丙午` 연주 / `庚寅` 월주를 반환한다. `04:01`에선 `乙巳` / `己丑`로 출력돼 조기 경계 전환이 확인된다.
- **이것은 결함 원인 발견이지 실제 명식 엔진의 승인이나 시간대 변환 코드 수정이 아니다.**

## 현재 범위의 테스트와 이후 해야 할 작업

1. Stage 2C 새 브라우저/Node QA 테스트를 GitHub 실제 번들에 실행해 24개 시각 비교가 재현되는지 확인한다.
2. KASI 공식 월력요항 및 2000년 등 다른 연도 자료로 연간 재현성을 검증한다.
3. 한국 지역 경도 보정 vs KST를 그대로 적용할지, 역사적 시차 및 서머타임 정책을 확정한다.
4. **연·월주 절입 비교용 시간**과 **일·시주 산출 기준 시간**을 분리해 구현하고, 입춘·경칩 경계 전후 1분 시나리오를 교차 검증한다.
5. 출생 시간 미상, 야자시(23:00~00:59), 음력 및 윤달 정책을 결정한다.
6. 그 후에만 `backend/chart_service.py`의 `unavailable` 상태를 실제 개인 계산으로 전환한다.
