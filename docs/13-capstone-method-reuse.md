# 첨부 교육 가이드에서 포포으로 가져온 방법론

**참고 문서:** `ALEPH_캡스톤_프로젝트_가이드_v0.6.1.pdf` (제공일 기준 2026-10-28 판, 25쪽)  
**참고 범위:** 4.3절(작업 기록), 8.2절(시험 실행·기록), 9.2~9.5절(포트폴리오·추적표·공개 자료), 7.7절(Agent 검증 원칙).

## 먼저 구분할 것

첨부 가이드는 **기업 보안 인프라 및 AI Agent 보안 운영 캡스톤 프로젝트**의 가이드입니다. 포포(B2C 운세 서비스)과 **다른 프로젝트**입니다. 첨부 문서의 보안 장비 구축, Firewall·VPN·IPS·WAF·SIEM 요구를 포포의 실제 수행 과제나 공식 평가 기준으로 옮기지 않았습니다. 본 저장소에 원본 PDF는 공개하지 않습니다.

## 서비스기획 산출물로 차용한 방식

| 가이드의 기록 원칙 | 포포 적용 | 저장 위치 |
|---|---|---|
| 요구사항→정책→실행→증거 연결 | 기능 ID와 UI 상태, 테스트 ID, 증거 파일의 관계표 | `docs/11-requirement-test-evidence-matrix.csv` |
| 예상과 실제 결과를 구분 | 아직 실행하지 않은 테스트는 `미실행`; 데이터 없는 성과는 `미검증` | `qa/01-test-cases.csv` |
| 실패·수정·재시험 기록 | 테스트 실행 폼에 초기 실패를 지우지 않고 후속 실행 ID 추가 | `qa/02-execution-template.md` |
| 도구 실패·근거 부족·악의적 입력 검증 | AI 상담 적용 가능성을 중심으로 **평가 계획만** 작성 | `docs/12-ai-evaluation-plan.md` |
| 공개본에서 비밀·개인정보 제외 | 예시 출생 데이터와 모델·로그의 개인정보 보호 | `docs/14-public-release-checklist.md` |
| 담당·직접 검증 범위 구분 | 기획/시안과 구현/실험을 나누어 표시 | `PROGRESS.md`, `evidence/README.md` |

## 직접 적용하지 않는 것

- 첨부 문서의 **15일·150시간·4~6명 팀·예산 1만 원** 조건은 포포 일정/팀 규모/예산이 아닙니다.
- SIEM 조사 에이전트의 **MCP·RAG·Memory·6유형 구현 의무**도 포포 AI 상담의 확정 요구사항이 아닙니다.
- 캡스톤의 시험 ID `IT-01~16`이나 평가 방식 역시 포포에서 수행했다고 주장하지 않습니다.
- 포포의 `AI 사주 상담`은 현재 **규칙·명식 기반 문맥을 제공하는 대화 기능 기획**이며, 별도의 AI Agent 시스템을 구현했다고 표기하지 않습니다.

**취업 포트폴리오 활용:** 기술 가이드에서 익힌 산출물 추적성·증거 중심 보고 방식만 새 B2C 도메인에 적용한 사례로 설명합니다. 실제 테스트가 실행되면 이 표의 상태와 증거 경로를 갱신합니다.
