# POPO Stage 2D — 절기 시각과 출생 시각의 분리 계산 검증

- 작성일: 2026-11-02
- 현재 상태: QA 전용 후보 구현. 실제 브라우저 검증/한국 역법 최종 승인 전.
- 기준 GitHub: `momoorr/POPO` main `b58aef2b1159b6d39d0be9d0c1c447d4083d06ca`.
- 기존 UI, `prototype/calc-core.js`, FastAPI 및 OpenAI Agent는 **수정하지 않는다**.

## 검증 배경

Stage 2A: 실제 브라우저 26/26 (2000년 날짜의 연월일주 비교 및 거부 조건), Stage 2B: 156/156 (KST 보정 전 시두법 규칙), Stage 2C: 2026년 KASI 24절기와 원본 라이브러리의 시각에 +60분을 더한 비교 24/24. Stage 2C에서 입춘 2026-02-04 04:30 KST 원본 엔진의 조기 연월주 전환이 관찰됨.

한국천문연구원 2026 달력자료는 입춘을 2월 4일 05:02로 공지하며, 원본 `lunar-javascript@1.7.7`은 04:02:08을 반환함. 원본 엔진이 실제 KST 시각보다 약 1시간 이른 절기 전환을 하는 것이 확인되지만 **그 자체로 한국 출생지의 전체 원국 계산 정책이 결정되지는 않음**.

- 공식 공개자료: https://astro.kasi.re.kr/life/post/calendarData?search_year=2026
- 공개자료는 연구원에서 '공식 발표 자료가 아니다'라고 고지함. 공식 월력요항은 별도.

## 실험 정책: 두 시계를 섞지 않고 구분하기

**실험 가정**: 오로지 2026년 KST 절기/연월주 경계를 분석하기 위해 연·월주 조회 시각을 표면적 한국 시각보다 60분 이전으로 옮긴다. 일주·시주는 원본 출생 시각을 그대로 사용한다. 실제 출생지를 고려한 진태양시/경도 보정, 자시 규칙, 역사 표준시는 미적용.

```text
KST 가상 출생 시각: 2026-02-04 04:30
  - 절입 경계 연월주 조회용 임시 시계: 2026-02-04 03:30 (원본 라이브러리 좌표계)
  - 일주/시주 시계: 2026-02-04 04:30 (KST 원본)
  - 따라서 QA 후보: 연주 乙巳, 월주 己丑
  - 원본 라이브러리를 한국 시각 그대로 부르면 연주 丙午, 월주 庚寅 (조기 전환)
```

## 검사 항목

`qa/kst-dual-clock-check.html`에서 기존 원본 라이브러리와 Stage 2C의 `qa/solar-term-kasi-2026-fixtures.js`를 불러온다.

1. 월주 전환에 관련된 12개 주요 절기(절입)를 KASI 게시 시각 -2분, +2분에 각각 검사.
2. 연주/월주만 절입용 시각으로 조회했을 때 12회 모두 경계에서 바뀌는지 점검.
3. 보정 전 계산이 경계 직전에 이미 바뀌어 있었는지 점검.
4. 시험 함수 내 일주/시주가 원래 KST 시각 산출값을 그대로 사용하는지 점검.
5. 입춘 04:30(조기전환) / 입춘 05:03(정상전환) 및 날짜 경계 넘어감을 별도 검사.

12개 절입 + 별도 보호 검사 4건 = **총 16건**. 2026년 외 다른 연도는 비교하지 않는다.

## 제품 사용 금지 조건

- 이 파일은 `qa/` 폴더에만 있으며 포포 프런트엔드 및 FastAPI 어느 쪽에서도 불러오지 않는다.
- 반환 객체는 `status: qa_only`, `verified: false`로 고정된다.
- 2026년 절입 주변의 월주 전환 검증이지 모든 연도/한국 지역/연월일시주 정확성 검증이 아님.
- 기존 `prototype/calc-core.js`의 1990~2040년, 매월 3~9일, 23:00~00:59, 음력/시간미상 등 제한 정책은 그대로 유지한다.
- AI Agent의 `backend/chart_service.py`는 계속 `unavailable / verified: false`를 반환한다.
