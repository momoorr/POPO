### UX-IMP-01 — 펼침·접힘 상태의 버튼 문구

- **화면:** SCR-03 / `COMP-TERM-01`
- **현재 동작:** 심화 열기/닫기 자체는 정상. 버튼 문구는 상태와 관계없이 `전문가 심화 설명 보기`
- **변경 요구사항:** 닫힌 상태 `전문가 심화 설명 보기`, 열린 상태 `전문가 심화 설명 접기`. `aria-expanded`와 표기 상태 일치
- **수용 기준:** 열기 → 문구/상태 변경, 접기 → 원래 문구 복귀, 키보드 조작 유지
- **검증 연결:** UXQA-04, UXQA-05

### UX-IMP-02 — 관계 유형별 결과 설명

- **화면:** SCR-11C
- **현재 동작:** 연인/친구 선택에 맞게 4개 카드의 **제목**은 바뀌지만 본문은 공통 설명을 사용
- **변경 요구사항:** `relationship_type`을 기준으로 카드별 예시 설명을 별도로 구성. 제목과 본문이 일관되게 변경되어야 함
- **정책:** 실제 궁합 계산 전에는 모든 결과에 `시연용` 표기를 유지하고, 사주에 근거한 개인화 판단인 것처럼 제시하지 않음
- **수용 기준:** 연인·배우자·가족·친구 각 4개 카드의 제목·내용이 주제에 맞게 표시됨. 내용이 개인의 감정/미래를 단정하지 않음
- **검증 연결:** UXQA-06, UXQA-09, UXQA-10

### UX-IMP-03 — 입력 오류의 위치 안내

- **화면:** SCR-11B
- **현재 동작:** 상대방(B)만 날짜가 비어 있어도 `나와 상대방의 가상 날짜를 모두 입력해 주세요.`라고 공통 안내
- **변경 요구사항:** 누락된 항목을 특정해서 안내. 예: `상대방의 생년월일을 입력해 주세요.`
- **수용 기준:** 나(A) 누락/상대(B) 누락/둘 다 누락/날짜 오류 각각 적절한 안내, 계산·시연 결과 진입 차단
- **검증 연결:** UXQA-07

## 변경 이력 및 증거 기록 방식

기능을 고칠 때는 `수정 파일·커밋`, `기대 결과`, `실제 결과`, `재검증 일자`, `스크린샷(비식별)`을 연결한다. **현재 위 세 개선 사항은 아직 구현하거나 재시험하지 않았다.**

기술 구현보다 중요한 기획 판단은 사용자가 이해하기 쉬운 상태 표현, 관계 목적에 맞는 정보 구성, 입력 오류 회복 경험을 설계하는 것이다. 개선 효과(완료시간, 만족도, 전환율)는 측정 전에는 기재하지 않는다.
