# POPO Stage 4F — 모바일 웹 단일 레이아웃 의사결정

## 배경

모바일 이용자가 많다고 가정하고, PC/모바일을 각각 별도 레이아웃으로 제작하기보다 **모바일 화면 하나를 중심으로 유지**하는 전략을 선택했다. 사주아이의 화면 구조는 사용자에게서 받은 벤치마크 관찰이며, 해당 사이트의 내부 구현 CSS와 실제 수치까지 확인한 것은 아니다.

## 이번 구현의 설계 규칙

- 앱쉘 최대 폭: 440 CSS px. 넓은 화면에서는 중앙 정렬 + 파스텔 외부 배경.
- 440px 이하: `width:100%`, 320px 최소 QA까지 텍스트와 그래프 너비를 유연하게 적용.
- 메인: Stage 4E.2의 **세로 모바일 일러스트**를 데스크톱에서도 일관되게 사용한다. **다른 이미지 생성 없음**.
- 내 사주: 네 기둥 → 오행 분포 → 종합 해석 → 상세 팝업. 중요 데이터는 팝업 없이 기본 화면에서 읽을 수 있도록 함.
- 오행 풍경: 기존 Stage 1.2의 다섯 장면을 유지하고, 요소 선택/세부 카드/비율/상징 탭을 세로로 구성.
- 하단 탭바는 데스크톱에서도 앱쉘 안에 고정되는 모바일 내비게이션으로 표시.
- Sabrina 로고, 부크크명조, 실제 HTML 버튼 및 키보드 포커스·기능 유지.
- 네이티브 앱은 만들지 않음. 향후 필요하면 PWA 검토 가능하나 현재 단계의 MVP 범위 아님.

## 신뢰·데이터 정책

현재 서비스는 전체 한국 만세력 정확성 검증 전이다. 공개 페이지는 **가상 예시 데이터**를 명확히 밝히고, 로컬 후보 계산은 `verified:false` 상태로만 별도 표시한다. 종합 해석은 개인에 대한 확정적 예언이 아니라 자료 구조를 이해하는 안내이며, 미검증 상태에서 AI 개인 풀이로 승격하지 않는다.

실제 스마트폰에서 외부 링크를 열어볼 수 있는 시연과 실제 AI Agent의 온라인 사용은 별개다. 5501/8000 로컬 포트는 개발 PC에서만 접근 가능하다. 출시형 MVP는 HTTPS API 배포/실제 만세력 기준 검증/안전한 인증 및 비용 제한이 뒤따라야 한다.
