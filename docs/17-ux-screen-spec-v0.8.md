## 1. 작성 목적과 범위

기존 [프로젝트 계획서](16-project-plan.md)와 [화면설계 추가안](10-screen-spec-addendum.md)을 바탕으로 다음 세 영역을 개발 가능한 단위로 구체화한다.

이번 문서는 **기획 산출물**이다. 현재 공개된 GitHub Pages는 클릭형 목업이며, 실제 명식 계산·AI API·궁합 계산은 연결되지 않았다. 이 설계를 바탕으로 구현을 시작한다.

## 3. 사용자 흐름 및 정보 구조

### 3.1 1차 기본 흐름

```text
홈(SCR-01)
  ├─ 내 사주 시작 → 출생 정보(SCR-02) → 명식 결과(SCR-03)
  │                                      ├─ 글자/용어 탭 → 용어 패널(COMP-TERM-01)
  │                                      └─ 주제별 풀이(SCR-04) → AI 상담(SCR-05)
  └─ 궁합 살펴보기 → 관계 선택(SCR-11A)
                      └─ 나·상대 출생정보(SCR-11B)
                          └─ 결과(SCR-11C) → 항목별 상세 보기 / AI 질문(연동 후)
```

**탐색 정책:** 모바일 하단은 기존 `홈 / 내 사주 / 운세 / AI 상담 / 전체` 구조를 유지한다. 궁합은 홈 카드와 `전체` 메뉴에 배치한다. 궁합만을 위해 탭을 6개로 늘리지 않는다. 실제 미구현 기능에는 `준비 중`, 목업에는 `시연용` 표시를 한다.

### 3.2 궁합 입력·결과의 연결 데이터

- `relationship_type`: `dating` / `spouse` / `family` / `friend`
- `person_a`, `person_b`: 각각의 출생 정보. 실제 필요 항목과 계산 범위는 SCR-02의 확정된 정책을 따른다.
- `person_a_chart_id`, `person_b_chart_id`: **실제 계산이 성공한 경우에만** 생성·참조한다.
- `policy_version`: 계산 및 궁합 해석 규칙 버전.
- `is_demo`: 예시 데이터인지 판별하는 명시적 플래그.
- `analysis_sections`: 관계 유형별 설명 항목과 근거. 사용 가능한 계산·해석 요소가 없는 항목은 생략 또는 준비 중 처리.

**궁합과 사주 계산은 별개:** 궁합 기능이 두 사람의 구조화된 명식을 사용하더라도, 관계 유형별 해석 로직은 따로 관리한다. 계산 불확실성이 있으면 근거 없는 점수나 미래 단정 문장을 반환하지 않는다.

## 4. SCR-01 — 홈 화면 개정

### 화면 목적

사용자가 포포 서비스가 무엇인지 이해하고, 처음 방문해도 '내 사주' 또는 '궁합'으로 이동할 수 있도록 한다.

| 구성 요소 | 표시 내용 | 사용자 행동 / 정책 |
|---|---|---|
| 브랜드 영역 | 포포(POPO) / 나를 읽는 AI 사주 상담 | 클릭 시 홈으로 이동 |
| 메인 비주얼 | **고양이처럼 살짝 올라간 눈매·긴 속눈썹의 새침한 달토끼 포포**가 달 절구에서 방아를 찧는 자체 일러스트 | 마스코트는 브랜드 안내자. 사용자별 일주 동물 캐릭터와 구분 |
| 메인 CTA | `내 사주 시작하기` | SCR-02로 이동 |
| 보조 CTA | `궁합 살펴보기` | SCR-11A로 이동. 미구현 동안 `시연용` 배지 표시 |
| 기능 카드 | 내 사주 / 관심 주제 / 궁합 / 운세 | 출시 상태 표시. 운세 일부·토정비결은 `준비 중` |
| 안내 문구 | 전통 해석의 한계, 목업 여부 | 실제 계산/AI 호출이 없는 경우 눈에 띄게 고지 |

**UI 방향:** 네이비 배경, 부드러운 라벤더 포인트, 아이보리 콘텐츠 카드, 금빛 별은 장식에만 절제해 사용. 캐릭터는 자주 바뀌는 정보가 아닌 브랜드 자산으로 관리한다. 사용자가 글을 읽거나 버튼을 누르기 어렵게 하는 반짝임 애니메이션은 넣지 않는다.

**화면 상태:** 기본/모바일 좁은 폭/이미지 로딩 실패/시연용 표기/키보드 포커스.

## 5. COMP-TERM-01 — 명리 용어 상세 패널

### 진입 화면

SCR-03 명식 결과에서 **일간·천간·지지·오행·십성** 등 글자 또는 정보 아이콘을 선택할 때 열고, SCR-04 심화 풀이에서도 동일한 컴포넌트를 재사용한다.

### 표시 구조

1. **표제:** 선택한 글자 또는 용어. 예: `일간(日干)`
2. **한 줄 설명:** 일반인이 이해할 수 있는 쉬운 뜻
3. **내 명식과의 연결:** 실제로 계산된 명식 필드에서 어떤 정보를 사용했는지 표시. 아직 계산되지 않은 경우 관련 부분을 **시연용**이라고 안내
4. **전문가 심화 보기:** 전통 명리학에서 사용하는 기술적 설명 펼치기/접기
5. **AI에게 추가 질문:** 실제 AI 연결 및 명식 문맥이 있을 때만 활성화. 그 외 `상담 준비 중` 표시

**예시로 사용할 수 있는 일반 개념 설명:** `일간은 태어난 날의 천간으로, 전통 명리학에서 자신을 해석하는 기준으로 활용합니다.` 이는 개인별 사주 결과가 아니다.

**인터랙션 정책**

- 모바일에서는 하단 시트, 데스크톱에서는 모달/측면 패널 중 디자인 시스템에 맞는 방식으로 제공한다.
- 열리면 포커스를 패널에 이동시키고 `닫기`, 바깥 영역 클릭, `Esc`로 닫을 수 있다.
- 닫은 후에는 이전 글자로 포커스를 돌려준다. 선택한 풀이 카테고리와 스크롤 위치를 유지한다.
- 동일한 명식 요소를 지칭하는 여러 위치에서 같은 설명 ID를 사용한다. 사용자가 보는 실제 문구는 검증한 콘텐츠로 관리한다.
- **학파·정책 미확정:** 격국·용신·신강·신약·신살은 계산·콘텐츠 규칙 검증 전 정답처럼 표시하지 않는다.

**빈/오류 상태:** 계산 근거 없음 → `현재 정보만으로는 이 항목을 설명할 수 없어요.` / 콘텐츠 없음 → 해당 용어의 상세 설명 준비 중 / 연결 오류 → 재시도 안내.

## 6. SCR-11A — 궁합 관계 유형 선택

### 목적

관계별로 궁금해하는 내용이 다를 수 있다는 가설에 따라 결과의 탐색 주제를 정한다.

| UI 항목 | 정의 | 행동·상태 |
|---|---|---|
| 화면 제목 | `어떤 관계가 궁금한가요?` | 관계를 확정적으로 판정하는 표현 지양 |
| 선택 카드 4개 | `연인`, `배우자`, `가족`, `친구` | 한 번에 하나만 선택, 설명 요약 표시 |
| 주요 CTA | `두 사람 정보 입력하기` | 관계 선택 전 비활성 |
| 정보 안내 | `관계를 이해하는 참고 콘텐츠로, 두 사람의 미래를 결정하지 않아요.` | 입력 전 고지 |
| 상태 표시 | 실제 계산 미구현 시 `시연용` | 이용자 오해 방지 |

### 관계 유형별 결과 항목 정의 (설계 제안)

| 유형 | 항목 1 | 항목 2 | 항목 3 | 항목 4 |
|---|---|---|---|---|
| 연인 | 감정 표현 방식 | 서로 편한 점 | 갈등 시 반응 | 대화 팁 |
| 배우자 | 생활·의사소통 | 협력 방식 | 의견 차이 | 장기 관계 팁 |
| 가족 | 표현 방식 | 서로 기대하는 점 | 거리감·갈등 | 이해·대화 팁 |
| 친구 | 친해지는 방식 | 함께하는 강점 | 불편해지는 상황 | 관계 유지 팁 |

이 항목들은 실제 사주로 검증된 개인의 성격 진단이 아니라 **콘텐츠 설계 단위**다. 실제 해석 문구는 규칙·근거 검증 뒤 작성한다.

## 7. SCR-11B — 두 사람 출생 정보 입력

### 목적 및 구성

- `나(A)`와 `상대(B)`의 영역을 분리한다. 착각하기 쉬우므로 이름 대신 `나`, `상대방` 레이블을 기본으로 사용한다.
- 양/음력·윤달·생년월일·출생 시간/모름·출생 지역 등 **필요한 항목은 SCR-02 정책을 재사용**한다.
- 실제 프로필 저장 기능은 1차 범위가 아니다. 공개 목업에서는 기본적으로 **가상 예시 정보로 체험**하도록 한다.
- 사용자 동의 없이 상대 출생 정보를 저장하거나 공유하지 않는다. 실제 수집·전송 이전에는 처리 목적과 보관 정책을 확정하고 안내한다.

| 상황 | 화면 동작 |
|---|---|
| 필수값 미입력·잘못된 날짜 | 해당 입력칸 아래 오류, 결과 단계로 이동 불가 |
| 출생 시간 미상 | 미상 옵션 허용, 시주를 추측하지 않음 |
| 두 사람 정보를 교환하려는 경우 | A/B 교환 버튼은 **후속 제안**; 1차에서는 직접 수정 가능 |
| 계산 지원 범위 밖 | 계산 불가 안내, 임의 데이터 생성 금지 |
| 시연 모드 | 실제 생일을 요구하지 않고 가상 정보로 결과 예시 보기 제공 |

**CTA:** `궁합 살펴보기`. 실제 계산 또는 명시적으로 선택한 예시 시연만 결과로 이동 가능하다.

## 8. SCR-11C — 궁합 결과

### 정보 우선순위

**관계·분석 기준 안내 → 한 줄 요약 → 항목 카드 → 상세 설명·근거 → 현실적인 소통 팁 → AI 질문** 순서로 구성한다.

| 구성 요소 | 화면 내용 | 정책 |
|---|---|---|
| 상단 카드 | `연인 궁합` 등 유형, `나 / 상대방` 구분 | 실명·생일을 기본 공개하지 않음 |
| 종합 요약 | 1~2문장으로 관계를 이해하는 관점 제시 | 실제 계산 근거 없으면 시연용 마킹 |
| 항목 카드 | 유형별 4개 카테고리의 간단한 설명 | 탭 시 상세 풀이 열기 |
| 근거 보기 | 사용한 명식의 요소 및 정책 버전 | 실제 계산 데이터 없이 생성하지 않음 |
| 소통 팁 | 현실적으로 생각해 볼 대화 질문/행동 | 상대 감정이나 미래 단정 금지 |
| AI 후속 상담 | `이 부분을 더 물어보기` | 두 명식+관계 유형+선택 항목 연결. 연동 전 비활성/준비 중 |

**점수 정책:** 삐삐사주처럼 100점 만점 수치를 보여주는 것은 현재 채택하지 않는다. 비교 지표와 점수 산식, 검증 절차가 마련되지 않았기 때문이다. 점수 대신 명확한 요약과 관계별 설명을 사용한다.

**예시 화면 문구(목업 전용):** `서로 다른 표현 방식이 있을 수 있어요. 대화할 때 어떤 점을 확인하면 좋을지 함께 살펴볼게요.` **실제 사주 결과가 아님**을 화면에 표시한다.

### 오류·준비 중 처리

- 상대 정보 누락 → 입력 화면으로 돌아가 해당 위치에 오류 표시.
- 두 명식 중 하나 계산 불가 → 관계 분석 생성하지 않고 사유 안내.
- 결과 생성 실패 → 재시도 제공, 중복 호출 방어.
- 검증된 해석 규칙이 없음 → 분석 대신 `현재는 화면 시연만 제공해요.` 표기.
- AI 서버 미연동 → 상담 버튼을 실제 응답으로 오해하지 않도록 `준비 중` 처리.

## 10. 사용자 검증 계획

사용성 테스트는 실제 수행 전이며 아래 과제로 검증한다.

| 과제 | 관찰 포인트 | 성공 판정의 방향 |
|---|---|---|
| T-01 내 사주에서 `일간` 의미 찾기 | 처음 발견까지의 경로, 의미를 이해했는지 | 힌트 없이 설명 찾고 자기 말로 요약 |
| T-02 친구 궁합 결과 찾기 | `궁합` 메뉴 인지, 관계 선택·입력 혼동 | 친구 선택 후 관련 결과 카드에 도달 |
| T-03 결과에서 AI 상담으로 이동하기 | 예시/실제 기능 상태 구분, CTA의 이해 | 준비 중임을 이해하고 흐름을 설명 |
| T-04 홈 캐릭터 인상 평가 | 동물 종류·브랜드 기억, 가독성 | 브랜드 캐릭터를 떠올리며 시각적 방해 없음 |

결과 기록 예시 필드: `참여자 ID(가명) / 과제 / 성공 여부 / 막힌 지점 / 인용(동의 시) / 개선안 / 수정 후 재시험`. 목표 수치나 개선율은 실제 테스트 전에는 만들지 않는다.

## 11. 구현 인계 및 변경 이력

### 구현 순서

1. **캐릭터 자산과 SCR-01 개정:** 달토끼 대표 일러스트 확정 → 홈 교체 → 반응형/접근성 확인.
2. **COMP-TERM-01:** 명식 요소별 용어 데이터와 패널 동작 → 쉬운/심화 설명 연결.
3. **SCR-11A~C 시연 화면:** 4개 관계 선택, 가상 A/B 입력, 결과 카드, 명확한 `시연용` 표시.
4. **실제 연동:** 계산 엔진·궁합 로직·서버 AI 모델 검증 완료 후 시연 데이터를 실데이터로 단계적 전환.
5. **QA·사용성 테스트:** 위 수용 기준으로 테스트 기록 및 수정 이력 작성. 구현 결과는 README의 현재 상태표에 반영.
