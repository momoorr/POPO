# POPO Stage 5C.4 — 작업을 시작한 화면으로 복귀

## 사용자 문제

Stage 5C.3까지는 수정/신규 저장의 성공 경로가 모두 마이페이지를 열었다. 보관함에서 프로필을 관리하던 사용자가 저장할 때마다 한 단계 밖으로 나갔다. 보관함에 항상 있는 목록 새로고침 버튼도 자동 갱신이 있어야 할 동작을 사용자에게 요구하는 인상을 주었다.

## 구현

`resetForm(row, origin)`에서 복귀 위치를 기록한다. 보관함의 수정/추가 진입은 `vault`, 마이페이지의 바로 등록은 `account`이다. 저장 응답의 프로필 ID를 확인한 이후 `vault`면 목록을 보여주고 소유자 조건으로 새 조회를 수행한다. `account`면 기존의 검증된 계정 열기 동작을 유지한다. 삭제도 성공 ID 확인 후 같은 목록을 재조회한다.

수정 폼의 취소/X/Esc는 진입한 화면으로 돌아간다. 목록의 X/Esc는 마이페이지를 연다. 시간 선택창은 별도 dialog이며 Escape 한 번이 두 단계를 동시에 닫지 않도록 기존 동작을 유지한다.

정상 화면의 수동 새로고침 버튼을 제거한다. 실패한 목록 조회를 위한 별도의 재시도 버튼만 필요할 때 보인다. 저장/삭제는 완료됐으나 조회가 실패한 경우 사실을 구분해 안내한다. 재시도는 SELECT만 수행한다. 실패하거나 불확실한 쓰기 요청을 자동 반복하지 않는다.

## 유지 사항

수정·삭제 위치, 글꼴, 아바타, 입력 검증, 프로필별 소유자 필터, `getUser()` 검증, 중복 제출 방지, 불확실한 신규 저장의 UUID 재사용은 유지한다. 계정 변경 시 기존 입력과 목록을 지우고 늦게 도착한 응답을 무시한다. DB 마이그레이션과 공개 배포는 포함하지 않는다.

## 검증 구분

모의 Supabase 응답을 사용한 브라우저/오프라인 검사와 설치·롤백 검사를 수행한다. 실제 DB/API는 연결하지 않았다. 사용자의 Windows, 실제 모바일 기기 및 카카오 계정에서의 확인은 적용 후 별도 수행한다.
