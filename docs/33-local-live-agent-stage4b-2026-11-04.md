# POPO MVP Stage 4B — 기존 채팅 화면에 실제 Agent API 연결 (로컬 QA)

- 기준: `momoorr/POPO` commit `3164ae5ae4f6b9623dbfe7f65c1013a1628fadc7`.
- 사용자: 개발자가 아닌 서비스기획 포트폴리오 기준으로 *작동하는 도구·근거 있는 해석·예외 처리·UX 유지*를 검증한다.
- 범위: **로컬 HTTP 웹**에서만 기존 상담 form과 FastAPI `/api/chat` 연결. GitHub Pages의 원래 시안 유지.

## 의사결정

1. 기존 `prototype/app.js`의 고정 시연 핸들러를 직접 수정하지 않고, 로컬일 때만 `submit` 캡처 이벤트로 실제 서버에 연결한다. 공개 GitHub Pages는 기존 동작 그대로 유지한다.
2. 전송 질문(최대 600자)과 **최근 6개 성공 메시지**(메시지당 최대 800자)만 웹 페이지 메모리에 보관하여 FastAPI의 `history` 필드로 전달한다. 새로고침하면 초기화되며 별도 브라우저 저장소에 기록하지 않는다.
3. 서버에서 받은 AI 답변은 `textContent`로 출력한다. HTML을 삽입하지 않는다.
4. 현재 계산 신뢰 경계는 `verified:false`, `chart_verified:false`, `can_personalize:false`를 유지한다. 개인 명식과 AI의 연결은 **아직 P0 미완료**.
5. API 지연 시 응답 대기 문구, 네트워크 실패·예산 차단·키 누락·오류 때 사용자에게 이해 가능한 메시지를 표시한다. 실패한 질문은 문맥에 넣지 않는다.
6. 프런트엔드는 키를 보유하지 않는다. API 키는 FastAPI 프로세스 환경변수. API 호출은 실제 비용 발생 가능. 로컬 HTTP에서만 요청이 발생하며 공개 도메인에서는 사용하지 않는다.

## 이번 단계에 포함하지 않음

- 공개 HTTPS FastAPI 배포, 실제 사용자 인증/레이트리밋/강제 지출 제한, 사용량 검증.
- 한국 만세력 전체 검증, 실사용 개인 출생정보, 오행/명식 시연 데이터 개인화.
- AI 답변 길이 제한 및 품질 자동 평가; 답변 중단 원인 조사는 별도 QA로 수행.
- Figma UI 수정, 디자인 대체, 궁합·토정비결 구현.

## 로컬 테스트 흐름

1. API 키가 지정된 FastAPI `127.0.0.1:8000` 실행, 웹 `127.0.0.1:5501` 실행.
2. `http://127.0.0.1:5501/prototype/index.html#chat`에서 먼저 **일반 오행 질문 1회**(소액 유료 호출) 테스트.
3. 고정된 기존 시안 응답이 중복 생성되지 않는지 확인.
4. 후속 질문은 테스트 후 진행. 개인 명식은 AI가 조회할 수 없음을 안내해야 하고 가짜 명식을 만들면 실패다.
5. GitHub 반영은 사용자 로컬 QA 증거 확인 이후 결정.

**포트폴리오 기록:** 실제 도구 호출/응답과 검증 전 차단의 사례를 분리해 기록하며, 한국 역법 검증 완료나 AI 답변 품질 평가 완료로 과장하지 않는다.
