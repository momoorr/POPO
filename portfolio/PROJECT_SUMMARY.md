# 포포 · 기업 제출용 1페이지 프로젝트 요약

**프로젝트 성격:** 개인 B2C AI 사주·명리 서비스기획 및 인터랙티브 UX 목업  
**현재 단계:** PRD·IA·화면 흐름 설계 및 HTML/CSS/JS 목업 / **실제 역법·AI 기능 미구현, 사용자 검증 미실시**  
**서비스 정의:** 이해하기 쉬운 명식 풀이를 제공하고 관심 주제의 후속 질문으로 연결하는 개인화 명리 플랫폼

## 문제 가설

- 명리학 전문용어가 어려워 결과를 이해하기 힘들 수 있다.
- 정적인 결과만으로는 이용자가 원하는 후속 질문을 해결하기 어렵다.
- 계산된 사실과 전통적 해석의 근거가 섞이면 신뢰 판단에 혼란이 생길 수 있다.

> 세 문제는 사용자 조사 전의 **가설**입니다. 실제 시장·사용자에게 검증했다고 주장하지 않습니다.

## 제품 의사결정 및 이유

| 기획 판단 | 이유 | 확인할 지표/증거 |
|---|---|---|
| 명식 결과 우선 제시 | 입력 후 핵심 결과를 바로 확인 | 입력→명식 진입 성공률 |
| 쉬운 설명 + 심화 토글 | 초심자와 학습형 사용자의 서로 다른 정보 깊이 | 사용성 과제, 심화 이용률 |
| 상세 풀이→AI 질문 이동 | 질문 맥락이 끊기지 않도록 연결 | 질문 시작률·문맥 오류 |
| 비회원 체험 | 최초 이용 진입 장벽을 낮추는 가설 | 최초 입력 완료율 |
| 캐릭터·토정비결 후순위 | 핵심 P0 미완 상태에서 기능 확장 방지 | 개발 진행 상태표 |
| 명식 계산·AI 해석 분리 | 생성형 AI의 명식값 오류 가능성 통제 | 계산 재현성·응답 정확성 시험 |

## 실제 준비된 산출물

- PRD v0.3 기준에 연결된 v0.4 기능 추가 제안, 경쟁 벤치마킹, IA/사용자 흐름
- 모바일 우선 인터랙티브 UX 목업(정적 HTML/CSS/JS)
- 60갑자 캐릭터 ID 표(캐릭터 60종 제작 완료 아님)
- QA 설계, 요구사항↔테스트 추적표, AI 응답 평가 계획
- 편집 가능한 발표 PPT

## 면접에서 설명할 수 있는 핵심

"복잡한 명리 콘텐츠를 기능 나열로 설계하지 않고, 이용자가 자신의 명식을 이해하고 관심 주제로 질문을 이어가는 흐름으로 정의했습니다. 명식 계산은 AI 언어모델과 분리하고, 미확정 정책은 별도 관리했습니다. 현재는 기획과 목업 단계로, 사용자 문제·계산 정확성·실제 이용 지표는 이후 검증할 과제로 명시했습니다."
